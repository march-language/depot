Depot.Query

Depot.Query: composable query builder for in-memory and SQL execution.

Builds a query value from a Depot.Schema that accumulates operations (where, select, order_by, limit, offset). The query is lazy — no work happens until execute/2 (in-memory) or exec_sql/2 (PostgreSQL) is called.

In-memory usage (tests / in-memory Repo)

let q = Depot.Query.from(schema())
  |> Depot.Query.where_(fn row -> record_get(row, "age") > Some(18))
  |> Depot.Query.order_asc("name")
  |> Depot.Query.limit(10)

let results = Depot.Query.execute(q, all_rows)

SQL usage (PostgreSQL via Connection)

let q = Depot.Query.from(schema())
  |> Depot.Query.where_gt("age", "18")
  |> Depot.Query.order_asc("name")
  |> Depot.Query.limit(10)

match Depot.Query.exec_sql(q, db_conn) do
Ok(rows)  -> rows   -- List of record-like assoc lists
Err(msg)  -> []
end

SQL conditions are added with where_eq, where_ne, where_gt, etc. These are orthogonal to where_ (in-memory predicates) — use whichever suits the execution path.

Multiple where_ / where_eq etc. calls are AND-combined. Order of operations in execute/exec_sql:

  1. Filter (where predicates AND sql conditions, AND-combined)
  2. Sort (order_by fields — SQL path only, via order_parts)
  3. Offset (drop N rows)
  4. Limit (take N rows)
  5. Project (select mapping — in-memory only)

Types

typeDQueryDQuery = DQuery(a, List(b), c, d, e, f, List(String), List(String))#

DQuery(schema, wheres, select_fn, limit_val, offset_val, ast_query, order_parts, sql_params) schema : the Depot.Schema value (or None for from_table queries) wheres : list of predicate functions (each: row -> Bool), AND-combined select_fn : None or Some(fn) for projection (row -> projected_row) limit_val : None or Some(Int) — used by in-memory execution path offset_val : None or Some(Int) — used by in-memory execution path ast_query : Ast.Query used for SQL generation via Build/Compile; ORDER BY is NOT stored here — use order_parts instead. order_parts : pre-compiled ORDER BY items as strings, e.g. ["\"age\" ASC"]. Stored as strings to avoid March RC bugs with user-defined nullary constructors (Asc/Desc) inside Ast.SortDir. Appended to SQL at query execution time. sql_params : accumulated parameter values (in $1, $2, … order) for SQL WHERE conditions added via where_eq / where_gt / etc. IS NULL / IS NOT NULL conditions contribute nothing. Returned by to_params/1 and used by exec_sql/2. Named DQuery (matching its sole constructor) rather than Query to avoid a type-name collision with Build.Query: when both types are named Query, the exhaustiveness checker merges their constructors and flags every match on a DQuery as missing the Query(QueryFields) case.

fnto_paramsto_params(query) : List(String)#

Return the ordered list of parameter values for the SQL generated by to_sql/1.

Values correspond to $1, $2, … in the SQL string in left-to-right order. IS NULL / IS NOT NULL conditions produce no parameter.

let params = Depot.Query.to_params(q)
-- ["alice@example.com", "18"]
fnto_sqlto_sql(query) : String#

Generate a parameterised SQL SELECT string from the query.

Uses the schema's table name and db_fields (non-virtual columns). SQL conditions added via where_eq / where_gt etc. become the WHERE clause. ORDER BY clauses added via order_asc / order_desc are appended last.

The $N placeholders match the list returned by to_params/1 — pass both to Db.exec/3:

let sql    = Depot.Query.to_sql(q)
let params = Depot.Query.to_params(q)
Db.exec(db_conn, sql, params)

Or use exec_sql/2 which does this in one step.

fnts_matchts_match(query, field, search_term)#

WHERE field @@ plainto_tsquery(search_term) — PostgreSQL full-text search predicate.

Column-type contract: field must already be a tsvector-typed column (e.g. maintained via a trigger or a generated column), NOT a plain text column and NOT a to_tsvector(...) expression. This predicate filters the bare column directly ("field" @@ plainto_tsquery(...)) — Postgres has no text @@ tsquery operator, so calling this against a plain text column is a SQL type error.

Indexing: to make this predicate use a GIN index, index the SAME bare tsvector column with Depot.Migration.create_index(table, [field], { using: "gin" }) — NOT create_index_expr. create_index_expr is for a DIFFERENT use case: indexing a computed to_tsvector(...) expression over a plain text column when you don't have a stored tsvector column. Querying against an expression index requires the WHERE clause to use the identical expression, which ts_match (a bare-column predicate) does not do — pairing ts_match with a create_index_expr index silently falls back to a Seq Scan.

ts_rank_expr/2 ranks the same bare tsvector column, so the two compose directly: ts_match(q, "body_tsv", term) + ts_rank_expr("body_tsv", term).

Uses a raw SQL Fragment; search_term travels as a bound Lit inside the Fragment's own argument list. This predicate compiles correctly via exec_sql/2 (which compiles $N params directly from the query AST). If you build SQL manually via to_sql/1 + to_params/1 instead, note this predicate's param will render correctly in the SQL from to_sql/1 (inlined, via compile_inline) but will NOT appear in to_params/1's list — prefer exec_sql/2 for queries using ts_match.

Depot.Query.from_table("articles") |> Depot.Query.ts_match("body_tsv", "postgres search")
fnts_rank_exprts_rank_expr(field, search_term)#

Builds a ts_rank(field, plainto_tsquery(search_term)) expression for use with Build.select_as/Build.order_by — ranking is a projection concern, so this returns an Expr, not a query. search_term is a bound Fragment param (same mechanism as ts_match), not a hand-concatenated literal, so it needs no manual SQL-escaping.

Same column-type contract as ts_match: field must already be a tsvector-typed column — pass the SAME field name given to ts_match so the rank reflects the same tsvector data being filtered.

Like ts_match, this Fragment param will NOT appear in to_params/1's list — prefer exec_sql/2 (or Db.exec with Compile.compile_parameterized) for queries built with ts_rank_expr.

Depot.Query.ts_rank_expr("body_tsv", "postgres search")
